# Team Charter

This document defines the team operating agreement for the Project Course group.

## Team values

- Respect and constructive communication
- Clear ownership and accountability
- Transparency in progress and blockers
- Shared responsibility for quality
- Consistent documentation of decisions

## Roles and responsibilities

A 4-person team can divide work in a way that matches the project and course goals. Suggested roles:

### 1. Project lead / coordinator

- keeps the schedule aligned,
- monitors task progress,
- ensures meeting notes and action items are recorded,
- coordinates decisions and escalation when needed.

### 2. Development lead

- owns implementation architecture decisions,
- keeps the codebase consistent,
- supports technical planning and review.

### 3. Quality and testing lead

- validates functionality,
- ensures test coverage and validation checks,
- documents quality issues and verification steps.

### 4. Documentation and product support lead

- maintains project documentation,
- supports user-facing clarity and product understanding,
- tracks requirements and project goals.

These roles can be adjusted as the project evolves, but the responsibilities should remain explicit and visible to the whole team.

## Team agreement

- We will maintain a respectful, inclusive working environment.
- We will communicate clearly about deadlines, blockers, and dependencies.
- We will be honest about workload and remaining tasks.
- We will review each other's work before merging.
- We will keep the repository organized and explain decisions in writing.

## Attendance and communication

- Attend scheduled meetings unless there is a valid reason not to.
- Share progress updates in the team communication channel.
- Flag blockers early enough for others to help.
- Keep meeting notes concise and actionable.

## Decision making

- Prefer consensus where possible.
- If a decision is time-sensitive, the responsible person may choose a direction, but it should be documented.
- Major design or scope changes should be discussed with the full team before implementation continues.

## Expectations

The team should aim for a sustainable rhythm:

- regular updates,
- predictable delivery,
- visible task ownership,
- clear documentation,
- shared accountability for final results.
